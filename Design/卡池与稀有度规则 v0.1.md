# 卡池与稀有度规则 v0.1

> 实现：`src/pool/`。试验页：`/pool-lab`。
> 范围：基础池（Mutualify 名单）与本人卡（osu! OAuth）。签名卡不在此文。

---

## 1. 数据从哪来

| 项 | 来源 | 说明 |
|---|---|---|
| 玩家名单 | Mutualify 公开排行榜 `/api/rankings?offset=` | 每页 50 人，按粉丝数降序。接口公开，但外层有 Cloudflare，脚本直连会被挡 |
| 玩家名单（备选） | 第三方卡池导出（如 osugacha.com `/api/players`） | 每页 30 人，需要该站账号；导出后直接用 `normalizeMutualify` 导入 |
| 完整资料 | `scripts/sync-osu.mjs` | client credentials 逐个拉 `/users/{id}/osu`，落成 `data/osu-players.json` |
| 头像 | `https://a.ppy.sh/{id}` | 地址可按 id 拼，浏览器渲染卡面时再拉。数据源自带 `avatarUrl` 时优先用它 |
| banner | 数据源的 `coverUrl`，或 `/me/osu` 的 `cover.url` | 两种形式，都不能按 id 拼，见下 |
| 本体卡数值 | `/me/osu` | PC、TTH、等级、成就、pp、ranked set、等级分布 |

### 1.1 banner 的两种地址

```
预设封面  https://assets.ppy.sh/user-cover-presets/{presetId}/{hash}.jpeg
自定义封面 https://assets.ppy.sh/user-profile-covers/{userId}/{hash}.jpeg
```

- 预设封面是有限集合，同一张预设的 `hash` 固定，图片可以本地缓存；
- 自定义封面按用户生成，`hash` 是文件标识，换封面就变；
- 两种都必须先知道它属于谁，无法从 `userId` 推导。

因此 banner 只能来自「别人已经采集过的数据」或「本人认领」。头像不受此限制。

Mutualify 的响应里 **没有** banner、pp、ranked set、等级分布。所以：

- 基础池的稀有度只能先靠粉丝数和一个 seed 定；
- ranked set / 等级分布是「本人认领后的确认项」，不是基础池的入场券；
- banner 在认领前一律显示占位。不要为了补 banner 去扫 `/users/{id}`。

`/api/friends` 与 `/api/friends/{id}` 是好友关系，默认不公开，卡池不需要，也不应拉。

## 2. 一个数字定占比

`sharesFromSeed(seed)` 用 mulberry32 在 `BASE_SHARE` 附近抖动 ±10%，再归一化：

| 档 | 目标占比 |
|---|---|
| C | 46% |
| UC | 24% |
| R | 14% |
| E | 9% |
| L | 4.5% |
| Radiant | 2% |
| Prismatic | 0.5% |

换 seed 会重洗落档，档位数不变。配额用最大余数法补齐，保证总和等于人数。

## 3. 谁排前面

`signalOf` 决定排序，不直接决定档：

```
signal = 100 * log10(1 + 粉丝数)
       +  60 * log10(1 + 谱面关注数)          // mappingFollowerCount，未知则跳过
       +  40 * log10(1 + ranked + gd + loved) // 作图数量，未知则跳过
       +  20 * log10(1 + popularity)          // 第三方热度分，未知则跳过
       +  10 * log10(1 + pp)                  // 未知则跳过
       +  40 * log10(1 + ranked set 数)        // 未知则跳过
       +  12 * log10(1 + 等级分布加权分)        // 未知则跳过
```

等级分布加权：SSH 1.2 / SS 1 / SH 0.7 / S 0.55 / A 0.2。

按 signal 降序切配额：先切 Prismatic，再 Radiant，一路到 C。所以高粉、高谱面关注、高作图量的人优先进入高稀有度。Mutualify 只给粉丝数时，其余项为 0，不扣分。

## 4. 国榜下限

| 国内名次 | 下限 | 生效条件 |
|---|---|---|
| 1–10 | Radiant | 该国有排名玩家 ≥ 10 |
| 1–50 | L | ≥ 50 |
| 1–200 | E | ≥ 200 |
| 1–1000 | R | ≥ 1000 |

「有排名」指 Mutualify 返回的 `globalRank` 非空。名次按各国 `globalRank` 升序排，粉丝数只做同分决胜。

国家人数不够时该档不生效，避免 3 人小国整国变 Radiant。

**副作用**：32 个国家 × 前 1000 名 ≈ 3.2 万张 R。10 万池里 R 会从 14% 涨到 30% 左右。这是「固定名次」的必然结果。想压回 20% 以内，就调小 `COUNTRY_FLOORS` 里的名次或去掉 R 档。

## 5. 本人卡

`heroIndex` 只吃 `/me/osu`：

```
index = 18 * log10(1 + PC)
      + 14 * log10(1 + TTH)
      + 1.2 * 等级
      + 8 * log10(1 + 成就数)
      + 6 * log10(1 + ranked set 数)     // 有则加
      + 4 * log10(1 + 等级分布加权分)     // 有则加
      + 5 * log10(1 + pp)               // 有则加
```

映射到设计文档规定的 UC–L 区间：

| index | 档 | 强度基数 |
|---|---|---|
| ≥ 105 | L | 960 × 0.9–1.1 |
| ≥ 75 | E | 740 × 0.9–1.1 |
| ≥ 45 | R | 600 × 0.9–1.1 |
| < 45 | UC | 480 × 0.9–1.1 |

本人卡的卡面稀有度用这个档，池里的镜像卡保持入池时的档，不随认领漂移。满养成后仍按 `经济与养成系统 v0.2 §8` 走向 Prismatic 强度。

## 6. 下架

`revoke(card)` 只写 `hidden: true`，同时清掉 `hero` 和 `coverUrl`。

- 抽卡和浏览都跳过 `hidden`；
- 重新导入同一份 Mutualify 数据时，`buildPool` 按 `osuId` 保留旧行，已下架的人不会被放回来；
- 恢复上架只翻 `hidden`，不需要重新计算。

## 7. 第三方卡池的做法（观察记录）

osugacha.com 的 `/api/players` 每页 30 人，返回字段可以直接映射到 `MutualifyRow`：

| 字段 | 用途 |
|---|---|
| `id` / `username` / `countryCode` | 身份 |
| `avatarUrl` | 带缓存戳的头像地址 |
| `coverUrl` | 预设或自定义封面 |
| `followerCount` | 主信号 |
| `mappingFollowerCount` | 谱面关注数 |
| `rankedMaps` / `guestMaps` / `lovedMaps` | 作图数量 |
| `popularity` / `pp` / `globalRank` | 热度与强度 |
| `lastSyncedAt` | **后端同步时间** |
| `currentRarity` / `mintedCount` | 他们自己的发行状态 |

`lastSyncedAt` 说明他们不是前端拼地址，而是后端定期调 osu API 同步每个玩家，把 `avatarUrl`、`coverUrl` 和上面这堆信号落库。卡面只是读库。

这份抓包的价值是字段设计，不是数据本身：抓包工具会截断长响应，拿不到完整分页，而且对方的限流约 300 次/窗口。

## 8. 目前没做的

| 缺口 | 原因 | 需要什么 |
|---|---|---|
| 未认领卡的 banner | 需要先知道封面地址 | 跑 `scripts/sync-osu.mjs`，`cover.url` 会写进 `coverUrl` |
| 基础池的 ranked set / 等级 | 需要逐个读用户 | 同上，脚本会填 `rankedMaps` / `guestMaps` / `lovedMaps` / `grades` |
| 下架状态持久化 | 试验页只存在内存 | 后端 `pool_cards.hidden` 或本地存储 |
| 10 万名单的自动同步 | Cloudflare 挡脚本 | 浏览器控制台导出 id 列表，再交给 `sync-osu.mjs` |
| 国榜名次的跨期稳定 | 名次随池子人数变 | 固定快照日期，或在库里存 `snapshot_at` |

## 9. 性能

10 万条导入 + 排序 + 分档 + 国榜下限，实测约 77ms（浏览器，2026-11）。卡面只渲染当前页 48 张，头像按需从 `a.ppy.sh` 拉。

# M1 验收清单

> 范围：**账号 + 卡池 + 抽卡 + 收藏**。验收口径：能注册（首次 osu! 登录即建号）、能抽、能在卡册看到卡。
> 最后执行：2026-11-08
> 执行环境：Windows / Node v24.22.1 / pnpm 12.16.1 / 临时 PGlite（导入 7 张 sample）/ API 临时跑在 3199 以避免占用本地 3100。
> 结论：**核心 API、`/gacha`、卡册筛选/分页、卡牌详情、桌面真实开包、退出登录均已复验；真实 osu! OAuth 往返仍需用你的账号完成一次。**

## 0. 前置条件

在仓库根目录：

```powershell
pnpm install
copy .env.example .env
# 编辑 .env：OSU_CLIENT_ID=74418、OSU_CLIENT_SECRET、SESSION_SECRET
pnpm import:sample
```

> 导入时 API 必须是停止状态。PGlite 单进程单连接。

两个终端启动：

```powershell
# 终端 A
pnpm dev:api

# 终端 B
pnpm dev
# 如果前端用 5207：pnpm dev -- --port 5207 --strictPort
# 同时把 .env 的 WEB_BASE_URL 改成 http://localhost:5207，并重启 API
```

后续命令默认：

```powershell
$base = "http://localhost:3100"
```

浏览器登录后，从 DevTools → Application → Cookies → `http://localhost:3100` 复制 `choke_session` 的值：

```powershell
$cookie = "choke_session=osu-123456.<签名>"
$me = curl.exe -s -H "Cookie: $cookie" "$base/auth/me" | ConvertFrom-Json
$uid = $me.data.id
$uid
```

> PowerShell 里 `curl` 可能是 `Invoke-WebRequest` 的别名，请统一写 `curl.exe`。带 JSON 的 POST 用 `'{"count":5}' | curl.exe ... -d "@-"`，避免引号被 PowerShell 吃掉。

### C. 抽卡

```powershell
# C1：普通池开 5 张
'{"count":5}' | curl.exe -s -X POST "$base/packs/normal/open" `
  -H "Cookie: $cookie" -H "Content-Type: application/json" -d "@-"
# 期望：ok=true；results 长度 5；seed 为数字；pity.before/after 连续
```

```powershell
# C5：60 抽保底。idle 池 L 权重只有 0.2%，通常 60 抽内不会自然出 L。
# 用新账号，或确保该账号 idle 池当前 counter 为 0；本地也可以备份后重建 PGlite 数据目录。
# 如果中途自然出了 L，counter 会归零，需要重新累计 60 抽。
1..6 | ForEach-Object {
  $r = ('{"count":10}' | curl.exe -s -X POST "$base/packs/idle/open" `
    -H "Cookie: $cookie" -H "Content-Type: application/json" -d "@-") | ConvertFrom-Json
  $high = @($r.data.results | Where-Object { $_.rarity -in @('L','Radiant','Prismatic') }).Count
  $pity = @($r.data.results | Where-Object { $_.fromPity }).Count
  "{0} -> {1}; high={2}; fromPity={3}" -f `
    $r.data.pity.before, $r.data.pity.after, $high, $pity
}
```

本次实测输出：

```text
0 -> 10; high=0; fromPity=0
10 -> 20; high=0; fromPity=0
20 -> 30; high=0; fromPity=0
30 -> 40; high=0; fromPity=0
40 -> 50; high=0; fromPity=0
50 -> 0; high=1; fromPity=1
```

判定：最后一组 `high >= 1` 且 `fromPity >= 1`，说明第 60 抽被强制为 `L`，随后 counter 归零。`before/after` 必须首尾相接。

### E. 端到端

1. 清空站点 cookie，重新走 osu! 登录。
2. `/gacha` 开 5 张，记住其中一张卡名。
3. 回桌面 → 卡册，找到这张卡。
4. 点开详情，确认卡面/技能/等级信息。
5. Ctrl+C 停 API，再 `pnpm dev:api`，刷新页面，确认仍登录且卡还在。
6. 在桌面点“发牌”，双击桌上卡包开包，结束后拖进卡册或点“快速收卡”，再去卡册确认。

### F. 安全

```powershell
# F1：无 cookie 读任意用户卡册 → 401
curl.exe -i "$base/users/osu-999999/cards"

# F2：A 的 cookie 读 B 的 userId → 403
curl.exe -i -H "Cookie: $cookie" "$base/users/osu-999999/cards"

# F3：无 cookie 开包 → 401
'{"count":1}' | curl.exe -i -X POST "$base/packs/normal/open" `
  -H "Content-Type: application/json" -d "@-"

# F4：篡改签名 → 401
curl.exe -i -H "Cookie: choke_session=osu-424242.deadbeef" "$base/auth/me"

# F5：伪造 state → 400
curl.exe -i "$base/auth/osu/callback?code=fake&state=fake"
```

F7（退出）：在浏览器点“退出”，到 DevTools 确认 `choke_session` 已消失；随后不带 cookie 请求 `/auth/me`，应为 401。**不要用 `-H "Cookie: ..."` 手动重放退出前的旧 cookie**：当前 session 是无状态 HMAC 签名，logout 只清浏览器 cookie，服务端不撤销旧签名，重放仍会返回 200。

F6（body userId 不参与鉴权）：用 A 的 cookie 开包，body 写别人的 id：

```powershell
'{"userId":"osu-999999","count":1}' | curl.exe -s -X POST "$base/packs/normal/open" `
  -H "Cookie: $cookie" -H "Content-Type: application/json" -d "@-"
# 期望：仍返回 A 的开包结果；随后 A 的卡册 +1，B 的卡册仍不可访问
```

F8：DevTools 里确认 `choke_session` 为 `HttpOnly`、`SameSite=Lax`、`Path=/`，`Max-Age` 约 30 天。

## 5. 剩余风险

| 风险 | 影响 | 建议 |
|---|---|---|
| 没有自动化测试和 CI | 回归只能靠手工，M1 之后的改动容易碰坏抽卡/鉴权 | M2 前补最小 API 冒烟测试（登录 mock、开包、卡册、401/403） |
| 真实 OAuth 未纳入验收 | `redirect_uri`、`client_secret`、state 任一配置错就无法登录 | 每次换环境先手工走一遍 A1/A2；回调固定 `http://localhost:3100/auth/osu/callback` |
| PGlite 单进程单连接 | API 运行时导入会冲突；不能多实例；进程崩溃时数据目录可能需恢复 | 导入前停 API；备份 `apps/api/.data/pg`；上线换 PostgreSQL |
| 全量卡池不入库 | 新克隆只有 7 张 sample，开包可能缺稀有度 | 按 README 构建/导入全量卡池；仓库只保留 sample |
| `import:cards --replace` 清空 `cards` | 旧 `user_cards` 可能指向不存在的卡 | 个人库先备份；正式环境需要迁移脚本和一致性检查 |
| 60 抽保底测试带随机性 | `idle` 池仍有 0.2% 自然 L，可能提前重置计数 | 用新账号/空闲池跑；或直接查 `pity` 表与 `pack_openings` 记录 |
| 没有独立保底查询接口 | 页面只能从开包响应拿 `pity`，刷新后显示 `—` | 后续补 `GET /gacha/pity` 或登录时返回保底状态 |
| session 仅靠 HMAC cookie | 服务端无 session 表，无法单个踢下线；logout 只清 cookie | M2 引入会话表/撤销机制（需求 DB-03） |
| 端口配置分散 | `PORT` 改了但 `vite.config.ts` 代理或 `WEB_BASE_URL` 没改，会出现 502/跳错页 | M1 固定 3100 + 5173；改端口按 README 三处一起改 |
| 无战斗/经济 | 不属于 M1 验收，但 UI 已有入口 | 验收时明确只对账号/卡池/抽卡/收藏负责 |

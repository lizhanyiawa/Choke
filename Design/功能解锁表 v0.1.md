# 功能解锁表 v0.1

> **2026-11-28 提示（砍单后）**：本文的**机制**（解锁表在 `content/unlocks.json`、服务端统一校验 `requireFeature`、前端读表）仍然有效；但下面这些已经过时，只当历史参考：
> - **玩家等级只当进度记号，不再按等级封锁功能**，今后改成随引导和主线进度开放（见 `设计原则与方向 v0.1.md` §5）。
> - 第 4 节经验来源里的「每日任务与活跃度宝箱、周常、月常、副本扫荡」都已删除，现在玩家经验只来自教程、主线首通、一次性成就、签到。
> - 第 5 节解锁表里的「喂养、副本、体力药水」功能已删除；任务系统现在只有成就、每日推荐谱面（暂无奖励）、签到。
> - 第 2 节、第 6 节、第 7 节里提到体力、副本、挂机包、体力药水的句子同理。

> 状态：**草案，数值全是占位**。已落地：解锁表 `content/unlocks.json`、共用判断代码 `packages/shared/src/unlocks.ts`、新的经验曲线（`content/progression.json`）、服务端统一校验、前端读表。测试是 `pnpm test:unlocks` 和 `pnpm test:feature-locks`。任务与成就的经验来源也加了（第 6 节第 3 步）；主线首通经验等主线地图。解锁提示、放慢新手引导还没做。
> 目标：新玩家第 1 天只看到开包、卡册、组队、战斗；前 3 天（约 Lv15）把主要功能陆续解锁完；Lv50 大约要三周多；Lv50–60 非常陡，当作长期目标。
> 经济数值（经验发多少、每天预算）最终由经济研究定，这里给的是目标曲线。

## 1. 原则

1. **解锁靠"做过"，不只靠等级**。每个新功能解锁时，配一条"第一次用它"的引导和一次性成就；做完这件事就发经验，把玩家推到下一个解锁点。这样等级只是进度的记号，引导才是主线。
2. **一次只多一两样**。每次解锁最多出现 1–2 个新入口，不要一口气把桌面铺满。
3. **服务端要校验**。前端的锁只是提示；绕过界面直接调接口也必须被拒绝（现在只有市场做到了）。
4. **玩家等级反映"体验了多少内容"**，不是肝度。所以重复刷的事（开包、市场买卖、重复扫荡）不发玩家经验。

## 2. 现状（代码里已有的）

- 前端写死了一份解锁表：`src/tutorial/unlocks.ts`。Lv1：账号、关于、开包、卡册；Lv2：卡组、战斗；Lv3：背包、图鉴、邀请函、发牌按钮、市场。后面五样要先完成新手教程。
- 新手教程现在的步骤：开包 → 卡册 → 卡组 → 战斗 → 毕业（`packages/shared/src/tutorial.ts`）。毕业时等级补到 Lv3（`tutorialGraduateLevel`）。
- **服务端已校验所有受限功能**（第 6 节第 2 步）。
- 出征点数随等级发（`content/progression.json` 的 `pointsByLevel`）：Lv1 给 8 点，Lv3、5、10、15、20…50 各 +3，Lv50 一共 41 点。
- 副本现在要先首通绑定的资源远征才能扫荡（服务端校验，`first_clear_required`）。
- 玩家经验来源：教程 250、副本每体力 1 点、资源远征首通 200–600、任务和成就和活跃度宝箱（占位值，见第 4 节）。开包、市场买卖不发经验。

## 5. 解锁表

"条件"一栏：**引导**指要先完成新手引导；**等级**指玩家等级；**正式账号**指绑定了 osu! 的账号（邮箱号和游客只能看）。表本体在 `content/unlocks.json`，下面是它的说明版。大约时间按第 3 节的曲线估。

| 功能 | 条件 | 参考等级 | 大约时间 | 服务端要校验 |
|---|---|---|---|---|
| 账号、关于、开包、卡册 | 开局 | Lv1 | 开始 | 不需要 |
| 卡组、战斗 | 引导推进到这一步 | Lv2 | 前 10 分钟 | 战斗接口校验已有卡组 |
| 背包、图鉴、邀请函、发牌 | **完成新手引导** | Lv3 | 第 1 天 | 否（只是入口） |
| **任务系统一次全开**：日常、周常、月常、成就、每日推荐谱面、签到 | 完成新手引导 | Lv3 | 第 1 天 | 是 |
| **市场** | 完成新手引导 + **正式账号**（绑定 osu!；游客和邮箱号只能看，不能上架和购买） | Lv3 | 第 1 天 | 是（已有） |
| 喂养、分解 | 引导 + 等级 | Lv4 | 第 1 天 | 是 |
| 主线远征（第一章） | 引导 + 等级 | Lv5 | 第 1 天 | 是 |
| 融合（升命座） | 引导 + 等级 | Lv6 | 第 1 天 | 是 |
| 副本（练习室、碎片矿脉、精华回廊） | 引导 + 等级 + 首通对应资源远征 | Lv8 | 第 2 天 | 是（首通已有，等级待加） |
| 体力药水、NPC 回收 | 引导 + 等级 | Lv9 | 第 2 天 | 是 |
| 远征难度档位 | 引导 + 等级 | Lv12 | 第 3 天 | 是 |
| 镀闪（闪卡精华） | 引导 + 等级 | Lv14 | 第 3 天 | 是 |
| 赛季远征 | 赛季开放 + 引导 + 等级 | Lv15 | 第 3 天 | 是 |
| 出征点数节点 | 等级：Lv3、5、10、15、20、25…50 各 +3 点 | Lv3–50 | 贯穿 | 是（已有） |

说明：市场的"参考等级"填的是 3，等于引导毕业时补到的等级，所以实际上只看"完成引导 + 正式账号"。以后要是改了毕业等级，市场照样跟着引导走。每日推荐谱面还需要玩家有 osu! 账号才有谱面可打，这是数据条件，不算解锁条件。

**后话（赛季开了或做了再排）**：通行证、个人主页、名片、战队、成就页的完整入口。

### 解锁时的提示

- 桌面上未解锁的物件继续显示锁定态，写"Lv.N 解锁"或"完成新手引导后解锁"（现有写法，保留）。
- 解锁的瞬间：弹一次提示（哪个功能、怎么用），并发一次"首次使用"成就的提示条；不强制走完。
- 第一次用某个新功能时，只做一次轻引导（高亮 + 一句话），不阻断操作。

## 6. 实现进度

1. ✅ **解锁表移到 `content/unlocks.json`**：每个功能一行，条件是等级、是否要完成引导、是否要正式账号（条件之间是"且"）。共用判断在 `@choke/shared/unlocks`（`lockReason`、`isUnlocked`、`lockMessage`）。
2. ✅ **服务端统一校验**：喂养、融合、镀闪、分解、NPC 回收（预览和执行）、副本扫荡、体力药水、任务与签到（含每日推荐谱面）、市场上架和购买，入口都用 `apps/api/src/unlocks.ts` 的 `requireFeature` 检查；没解锁返回 403 `feature_locked`，带 `feature`、`featureName`、`reason`（`level` / `tutorial` / `account`）和所需等级。出征按地图查：主线要 `mainline`，赛季要 `season`，副本图在地图文件里写 `"unlock": "dungeons"`，日常和周常不设限；`/expeditions/maps` 每张图带 `startable` 和 `lockedReason`。`GET /progress` 带上每个功能的锁状态 `locks`，前端直接用。等级、引导、是否绑定 osu! 全以数据库为准。
3. ✅ **经验曲线**：`content/progression.json` 的 `expTable` 重排；`pnpm test:unlocks` 校验 Lv15、Lv50 的累计经验和 Lv50 之后的陡度。✅ **经验来源**：任务奖励、成就、活跃度宝箱、签到的奖励里可以写 `playerExp`（`questRewardSchema`），领取时直接加到账号上，升级走 `addPlayerExp`（`apps/api/src/player-exp.ts`），不进邮件附件、不写流水；过期补发的邮件里经验已经直接到账，邮件正文会提一句。`content/quests.json` 已填占位值。⬜ 主线首通的经验等主线地图。
4. ◐ **前端**：✅ 读表（`src/tutorial/unlocks.ts` 不再写死等级，直接用 `@choke/shared/unlocks`；`/progress` 多返回 `linkedAccount`，进度缓存和 DeskBook 跟着带上；市场面板和卡牌详情的上架提示改用同一套规则，邮箱号和游客只能看）。✅ `AccountPanel` 的"登录状态"改成看 `/auth/me` 的 `kind`、`osuId`、`hasEmail`，并加了绑定 osu! 入口、二选一对比界面（`BindChoice.tsx`）、补邮箱表单。✅ 卡牌详情里的融合（含本体卡吞噬镜像）、镀闪、分解，以及卡册的批量分解和 NPC 回收：没解锁时按钮禁用，按钮提示和页签顶部写同一句话（`featureLockHint`，和服务端拒绝时的文案一致）。⬜ 解锁瞬间的提示、第一次使用的轻引导、放慢新手引导。
5. ✅ 测试：`pnpm test:feature-locks`（每个受限接口 Lv 差一级被拒、到了放行；引导没做完被拒；游客和纯邮箱号进不了市场但能看；出征地图列表；`/progress` 的 `locks`），已加入 `pnpm test` 和 `pnpm test:pg`。

## 7. 还没定的事

- 市场的防小号：**已定为只有绑定 osu! 的账号才能交易**，邮箱注册的号和游客一样只能看。所以要补"邮箱号绑定 osu! 并继承进度"，后端已经做完（`pnpm test:account-binding`），见备忘录和《养成与经济前端对接清单》第 6 节；前端的绑定入口和二选一界面还没做。
- 新手引导太快：现在只教到"战斗"一步，没有教喂养、融合、出征。建议每个新功能解锁时配一段轻引导（第 5 节末尾），并把引导拉长。具体怎么放慢在第 4 步和 fable 一起定。
- 挂机包、体力药水已取消，不用找入口；NPC 回收在卡册的批量处理里。
- Lv15 之后新功能很少，可能要给 Lv20–50 留一些"解锁感"（新章节、更高难度、新卡池），这依赖内容量，先不排。

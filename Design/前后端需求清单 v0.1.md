# Choke! 前后端需求清单 v0.1

> 范围：**第一版 = PVE 内测**（几十到一两百人）。PvP 在赛季末上线，本期只留接口位与结构位。
> 依据：[卡牌数值与战斗机制 v0.1](卡牌数值与战斗机制%20v0.1.md)、[经济与养成系统 v0.2](经济与养成系统%20v0.2.md)、[抽卡规则 v0.1](抽卡规则%20v0.1.txt)。

---

## 0. 技术栈与工程结构（已定，不重议）

| 层 | 选型 |
|---|---|
| 语言 | Node 22 + TypeScript |
| 后端 | Fastify |
| ORM | Drizzle |
| 数据库 | PostgreSQL 16（**唯一真相源**） |
| 实时 | Socket.io |
| 缓存 | Redis 7（**只做在线状态 / 房间 / 限流**，不缓存业务数据） |
| 前端 | React 19 + Vite 8 + Tailwind 4 + shadcn/ui + framer-motion + pixi.js |
| 部署 | 2C4G VPS + Docker Compose |

```
apps/web        # 现有 src 迁入
apps/api        # Fastify + Socket.io + Drizzle
packages/shared # 战斗规则 / 数值 / 抽卡概率（双端复用）
packages/db     # schema + migration
```

**明确不做**：微服务拆分、Redis 业务读缓存、帧同步。目标 300–500 并发，单机够用。

## 1. 共享规则层（`packages/shared`）—— 最优先

这份代码决定后面所有事能不能对得上。**必须是纯函数、无 IO、可回放**。

| ID | 模块 | 内容 |
|---|---|---|
| SH-01 | 数值 | 四维预算（恒 4.00）、7 档品质压缩比、派生值（HP/ATK/DEF/INT/迅捷标签） |
| SH-02 | 伤害 | `min(DEF/(DEF+10000), 0.70)`、物理/法术分流、近战/远程分类、属性 9 环克制、灵体 +20% |
| SH-03 | Combo | 命中 +1、未命中减半、回合结束清零、3=12% → 10=180% 曲线 |
| SH-04 | AP | 每回合 +2、上限 7（扩容 10）、**可继承**、开局 2、防御档位消耗、疲惫 +1、充能/霞艾拉、无偿（第 4 回合起） |
| SH-05 | 防御 | 三档/四档表（坦克 −20/40/70/90，非坦克 −20/30/50）、不可反悔、与减伤独立乘算 |
| SH-06 | 控制 | 硬控（3AP、打醒、精英限 2 次、警觉 3 回合）、软控魅惑、打断（盲 roll + 50/40/30%） |
| SH-07 | 状态机 | 荆棘（逐段固定反伤、每行动 3 段上限）、脆弱（受击 +30%）、狂暴、眩晕、迟缓、DOT |
| SH-08 | 蓄力 | 叠层增攻、满槽放大招、可打断 → 脆弱、变体狂暴、蓄力中仍普攻 |
| SH-09 | 支流程 | 支援结算 → 抢攻（4% 起手）→ 主队行动 → 敌方行动 → 回合结算 |
| SH-10 | 抽卡 | 卡包池 / 签名池隔离、SSR2/SR5/R15/材料78、20 抽保底、通行证 10 抽 |
| SH-11 | 掉落 | 副本产出、★0–★3 掉率加成、NPC 回收价表 |
| SH-12 | 校验 | 战斗回放校验（输入 + 种子 → 复算结果） |

> **为什么先做这层**：PvE 前端算、服务端只校验；PvP 必须服务端算。同一份规则两边跑，
> 才不会出现"前端伤害 3 万、服务端算出 2 万 8"的经典事故。

## 2. 数据模型（PostgreSQL）

| ID | 表 | 关键字段 | 备注 |
|---|---|---|---|
| DB-01 | `users` | id, 昵称, 头像, 创建时间, 封禁标记 | |
| DB-02 | `oauth_accounts` | provider, provider_uid, user_id | osu! OAuth |
| DB-03 | `sessions` | user_id, refresh_token_hash, expires_at, ua | |
| DB-04 | `cards`（静态定义） | id, 职业, 品阶, 四维, 技能 JSON, 属性, 版本 | 只读，配置导入 |
| DB-05 | `user_cards` | id, user_id, card_id, 等级, 经验, 命座, 签名等级, 绑定标记 | 实例 |
| DB-06 | `decks` / `deck_slots` | user_id, 槽位 1–7, user_card_id | 主队 7 张；侧面支援另表 |
| DB-07 | `battles` | id, user_id, 关卡, 种子, 开始/结束, 结果, 星级, 回放包 JSONB | |
| DB-08 | `runs`（大副本 v1.1 预留） | id, user_id, 路线节点, 恢复点, 进度快照 | 先建表不启用 |
| DB-09 | `pack_openings` | id, user_id, 池类型, 种子, 结果 JSONB, 保底计数前/后 | 审计用 |
| DB-10 | `currency_ledger` | id, user_id, 币种, 变动, 余额后, 来源类型, 关联 id | **双录，只增不改** |
| DB-11 | `market_orders` | id, seller, card, 价格, 状态, 过期 | |
| DB-12 | `market_trades` | id, order_id, buyer, price, 时间 | |
| DB-13 | `quests` / `quest_progress` | 日常/周常/月常、活跃点 | |
| DB-14 | `pass_progress` | 赛季、等级、已领奖 | 通行证 |
| DB-15 | `season` / `season_rewards` | 赛季起止、券折价、奖励 | |
| DB-16 | `mainline_progress` | 用户、章节、关卡、★记录 | |
| DB-17 | `route_ratings` | 用户、路线、最高星、时间 | 大副本预留 |
| DB-18 | `audit_log` | 谁、做了什么、何时 | 管理后台用 |

**硬约束**
- 所有经济变更必须写 `currency_ledger`，余额字段只是投影。
- 抽卡、市场成交、回收必须是**事务 + 幂等键**。
- `cards` 与 `user_cards` 分离：卡定义可热更，实例不动。

## 3. 后端接口清单

| ID | 模块 | 方法 / 路径 | 说明 | 优先级 |
|---|---|---|---|---|
| BE-01 | 认证 | `GET /auth/osu` | 跳转 osu! OAuth | P0 |
| BE-02 | 认证 | `GET /auth/osu/callback` | 换 token、建号、发 session | P0 |
| BE-03 | 认证 | `POST /auth/register` `POST /auth/login` | 邮箱路径 | P0 |
| BE-04 | 认证 | `POST /auth/refresh` `POST /auth/logout` | JWT / refresh 轮换 | P0 |
| BE-05 | 用户 | `GET /me` `PATCH /me` | 资料、设置 | P0 |
| BE-06 | 卡牌 | `GET /cards` `GET /cards/:id` | 卡池查询、筛选 | P0 |
| BE-07 | 卡牌 | `GET /me/cards` | 我的收藏 | P0 |
| BE-08 | 养成 | `POST /me/cards/:id/levelup` | 消耗经验 | P0 |
| BE-09 | 养成 | `POST /me/cards/:id/constellation` | 命座（镜像卡**或**碎片） | P0 |
| BE-10 | 养成 | `POST /me/cards/:id/respec` | 洗点 | P1 |
| BE-11 | 抽卡 | `POST /packs/:id/open` | 卡包开启（**服务端 RNG**） | P0 |
| BE-12 | 抽卡 | `POST /gacha/signature/draw` | 签名池（单抽/十连） | P0 |
| BE-13 | 抽卡 | `GET /gacha/pity` | 保底进度、通行证抽数 | P0 |
| BE-14 | 战斗 | `POST /battle/start` | 返回关卡配置 + 种子 | P0 |
| BE-15 | 战斗 | `POST /battle/submit` | 提交回放包，服务端复算校验 | P0 |
| BE-16 | 战斗 | `GET /battle/:id/replay` | 回放 | P1 |
| BE-17 | 主线 | `GET /mainline` `POST /mainline/clear` | 章节进度、星级 | P0 |
| BE-18 | 任务 | `GET /quests` `POST /quests/:id/claim` | 日常/周常/月常 | P0 |
| BE-19 | 通行证 | `GET /pass` `POST /pass/claim` | 等级 + 抽数 | P0 |
| BE-20 | 市场 | `GET /market/orders` | 订单簿（卡/价格/剩余） | P1 |
| BE-21 | 市场 | `POST /market/orders` `DELETE /market/orders/:id` | 挂单/撤单 | P1 |
| BE-22 | 市场 | `POST /market/buy` | 成交（PG 事务锁单） | P1 |
| BE-23 | 经济 | `GET /me/wallet` `GET /me/ledger` | 余额 + 流水 | P0 |
| BE-24 | 经济 | `POST /recycle` | NPC 回收（日限 20 张） | P0 |
| BE-25 | 赛季 | `GET /season` `POST /season/claim` | 当前赛季、券折价领取 | P1 |
| BE-26 | 管理 | `POST /admin/cards/import` `POST /admin/ban` | 配置导入、封禁 | P1 |

**统一约定**：全部接口走信封 `{ ok, data, error }`；错误带机器码；写接口必须带幂等键。

| FE-02 | 登录 / 注册 | osu! OAuth + 邮箱；已注册时按钮变「返回桌面」 | P0 |

| FE-08 | 战斗交互细节 | 打断"抽签"动画、硬控打醒提示、蓄力槽、状态图标栏 | P0 |
| FE-09 | 结算 | ★0–★3、掉落、回放保存 | P0 |
| FE-10 | 市场 | 订单簿、挂单、成交记录 | P1 |
| FE-11 | 任务 / 通行证 | 活跃点、等级、领奖 | P0 |
| FE-12 | 游戏指南 | 规则说明、术语表 | P1 |
| FE-13 | 版权声明 | 非盈利同人声明、osu! 素材授权说明 | P0 |

**交互原则**
- 一切"凹"的过程都要**可见**（打断抽签、抢攻触发、Combo 累积），否则玩家感受不到自己在赌。
- 意图预告是战斗 UI 的主角，不是附属信息条。

## 7. 非功能需求

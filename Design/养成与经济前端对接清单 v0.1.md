## 1. 卡牌养成总览：谁能干什么

| 操作 | 接口 | 材料 | 结果 |
|---|---|---|---|
| **喂养**（加经验） | `POST /users/:userId/cards/:userCardId/feed` | 任意卡（本体卡除外）+ 碎片 / 经验乐谱 | 经验折算后自动升级，过突破关自动扣金币 |
| **手动突破一级** | `POST .../level` | 卡里已攒够的经验 + 突破金币 + 同品质碎片 | 升 1 级 |
| **融合**（升命座） | `POST .../constellation` | 一张**同名**卡 | 命座 +1，**留下卡的技能原样保留** |
| **分解** | `POST .../dismantle` | 这张卡本身 | 得 4 个同品质碎片（闪卡另给精华） |
| **镀闪** | `POST .../enhance` | 精华 | 变闪卡 |
| **洗技能** | `POST .../reroll-skill` | 同品质碎片 + 金币 | 换掉 1 个技能槽，逢 5 自选（§8） |
| 看可用材料 | `GET .../fuel` | — | 同名重复卡列表 |

### 卡牌详情

图鉴（只读）和未拥有的卡只展示头部，不显示养成区块。

共同规则：**本体卡不能当材料、不能分解、不能上架**；**出征中的卡（参战卡锁定）不能被分解、被喂、被融合吃掉、上架**，返回 `in_expedition`。

### 1.1 喂养（`POST .../feed`）

请求：`{ cards: number[], items: [{ itemId, count }] }`，至少选一样；`cards` 最多 60 张且不重复，`items` 最多 20 种。不能喂给自己（`feed_self`）；目标满级返回 `max_level`。

- 一张卡折算的经验 = 该品质的基础喂养值 + 它已投入经验的 75%（`feedExpOf`）。闪卡另外给精华。
- 道具：`items.json` 里碎片（C 10 / UC 20 / R 48 / E 120 / L 288 / Mythic 720 / Prismatic 1920 经验）和经验乐谱（小 200 / 中 1000 / 大 5000）。
- 返回：`{ card, gained, wasted, levelsGained, coinsSpent, shardsSpent, shardItemId, blockedCost, blockedShards, coins, essenceGained, essence, items, consumedUserCardIds }`。
  - `wasted`：满级后溢出作废的经验，前端要提示。
  - `blockedCost` / `blockedShards`：见下节，大于 0 表示卡停在突破关了，分别是缺的金币和缺的碎片数。
  - `shardsSpent` / `shardItemId`：这次自动突破花掉的碎片数和碎片种类（没突破时为 0 / 缺省）。
  - `items`：喂完后的道具库存（最新值，直接覆盖本地）。

### 1.2 突破关（40 / 50 / 60 / 70 级，非本体卡）

升过这四级各要花**突破金币**和**同品质碎片**（R 卡吃 R 碎片，不能用别的品质顶）。数值在 `content/progression.json` 的 `breakthroughCoins`、`breakthroughShards`，前端预览用 `@choke/shared/progression` 的 `breakthroughCoinCost(level, isHero)` 和 `breakthroughShardCost(level, rarity, isHero)`。

| 升级 | 金币 | C / UC / R / E / L 碎片 | Mythic 碎片 | Prismatic 碎片 |
|---|---:|---:|---:|---:|
| `40→41` | 300 | 2 | 1 | 1 |
| `50→51` | 500 | 4 | 2 | 1 |
| `60→61` | 500 | 6 | 3 | 2 |
| `70→71` | 700 | 8 | 4 | 2 |

- **喂养时自动处理**：经验够了且金币和碎片都够，就自动扣掉继续升；**任何一样不够就停在该级**，剩下的经验保留在 `card.exp` 里不丢，返回 `blockedCost`（缺的金币）和 `blockedShards`（缺的碎片数）。两个都是 0 才表示没被卡住。
- 前端做法：`blockedCost > 0` 或 `blockedShards > 0`，或卡处于 40 / 50 / 60 / 70 级且 `card.exp >= expToNext(...)` 时，把喂养按钮换成"突破（N 金币 + M 片 X 碎片）"，点击调用 `POST .../level`（只升 1 级，成功返回 `{ card, spent, coinsSpent, shardsSpent, shardItemId, coins, items }`）。
- 手动突破的错误：金币不足 `400 not_enough_coins`（带 `need`、`coins`）；碎片不足 `400 not_enough_items`（带 `itemId`、`need`、`have`）；经验不够 `not_enough_exp`（带 `need`、`exp`）；满级 `max_level`。
- **没做**：阀门 / 进阶材料（《经济与养成系统 v0.3》§9）。界面上可以先留占位，但后端不会校验也不会扣。

### 1.3 融合（`POST .../constellation`）

- **普通卡**：消耗一张同名卡，命座 +1（上限 6）。不传 body 时自动挑等级最低、没被锁的同名卡；也可以传 `{ materialUserCardId }` 指定。没有同名卡返回 `no_duplicate`；同名卡全在出征里返回 `in_expedition`；满命座返回 `max_constellation`。返回 `{ card, consumedUserCardId }`。
- **本体卡**：命座上限 8，必须传 `{ materialUserCardId }`，且只能是自己的**镜像卡**（`missing_material` / `invalid_material`）；同一个玩家的镜像只能吞噬一次（`409 duplicate_source`）。返回里多 `constellation`、`resonance`、`summary`、`addedResonance`、`capped`。
- 预览共鸣属性：`@choke/shared/resonance` 的 `resonanceAttributeOf(job, mods)`；每次 +0.5%，单属性最多 3 次，满了提示"仅升命座，属性已达上限"（`capped: true`）。
- `GET /users/:userId/resonance` → `{ records, summary }`（`totalBpByAttr`、`countsByAttr`、`totalSlots`）。
- `GET /users/:userId/cards/:userCardId/fuel` → `{ rows }`：除目标卡自己外，所有"同名卡有两张以上"的实例（最多 60 条，按 pp 从高到低），做喂养 / 融合的材料选择列表用。

### 1.4 分解（`POST .../dismantle`）

无 body。除本体卡外任何卡都能分解，包括最后一张。得到 `SHARDS_PER_DISMANTLE`（4）个同品质碎片；升过级的卡另按"已投入经验 × 75%"折成经验乐谱返还（大 / 中 / 小拆分，尾数舍去）；闪卡另给精华。
返回：`{ removedUserCardId, itemsGained, essenceGained, items, essence }`。

### 1.5 镀闪（`POST .../enhance`）

body `{ action: "foil" }`（目前只有这一个）。花 `FOIL_COST` 精华把这张卡变成闪卡。已经是闪卡返回 `already_foil`，精华不够返回 `not_enough_essence`（带 `need`、`essence`）。返回 `{ card, cost, essence, action }`。

### 1.6 道具库存从哪来

`GET /auth/me` 的 `items` 字段，之后每次喂养 / 分解的返回里都带最新的 `items`。

## 2. 体力溢出槽（720）与体力药水

- **读取体力**：`GET /users/:userId/stamina`
  - 返回 `{ value, max: 360, overflowMax: 720, nextIn, potionUsedToday, potionDailyLimit: 2, potionCost: 100, potionGain: 60 }`。
  - 前端进度条建议拆为两段：`0–360`（6 分钟/点）主条 + `360–720`（12 分钟/点）溢出槽。
- **购买体力药水**：`POST /users/:userId/stamina/potion`
  - **100 金币 → +60 体力**，每日限 2 次，可充入溢出槽（720 封顶）。商店（§9）里也有这一项，两边共用同一个每日上限。
- **何时扣体力**：只有"拿到东西才扣"；主线和赛季远征不扣体力。副本入口 `POST /users/:userId/dungeons/:dungeonId/run`。

## 4. NPC 批量回收（日限 20 张）

## 5. 市场（押金、税率、价格带、7 天自动取消）

市场要**完成新手引导，并且账号绑定了 osu!**才能上架和购买，游客和只有邮箱的账号只能看。被拒时返回 `403`，code 为 `feature_locked`，带 `feature`（`market`）、`reason`（`tutorial` 或 `account`）、`level`、`message`（一句话提示，直接展示即可）。旧的 `guest_market` / `market_locked` 已经没有了。其他受限功能（喂养、融合、镀闪、分解、NPC 回收、副本、体力药水、任务、出征）被拒时是同一种格式，`reason` 还可能是 `level`；`GET /users/:userId/progress` 的 `locks` 一次给出所有功能的锁状态，详见《功能解锁表》。

- **看市场**：扁平页用 `GET /market/listings/page`（`q`、`rarity`、`type=pool|mirror`、`sort=new|asc|desc`、`limit`、`offset`），返回 `{ rows, total, limit, offset }`，挂单带 `expiresAt`。旧桌面仍用 `GET /market/listings`（最新 80 条）；`GET /users/:userId/market/listings` 返回自己的在售挂单，带 `deposit` 和 `expiresAt`。
- **上架**：`POST /users/:userId/market/list`，body `{ userCardId, price }`（价格 1 到 `MARKET_MAX_PRICE` 的整数）。
  - 上架时同时扣 **2% 上架税（`listTax`，至少 1，不退）** + **5% 押金（`deposit`，最低 1 金币）**；金币不够返回带 `listTax`、`deposit` 的错误。
  - 若已有历史成交，价格必须落在均价 **±40%** 区间内（超出返回 `400 price_out_of_band`，附带 `avgPrice / minPrice / maxPrice`）；单价上限 `MARKET_MAX_PRICE`。
  - 不能上架：本体卡（`hero_not_tradable`）、卡组里的卡（`in_deck`，先移出）、出征中的卡（`in_expedition`）、已在架的卡（`already_listed`）。
  - 返回 `{ id, price, listTax, deposit, coins, card }`。
- **下架**：`DELETE /users/:userId/market/listings/:listingId` → `{ id, depositRefunded, coins }`；满 7 天未成交也会自动取消。两种情况**押金全额退还**，**上架税不退**。
- **购买**：`POST /users/:userId/market/buy/:listingId`。
  - 扣买家 `price`；成交税 **5%**（`tradeTax`）从卖家货款里扣，卖家收到 `95% 货款 + 退还押金`。卡过户，并从卖家卡组里移除。
  - 错误：`not_found`（已被买走 / 已不存在）、`listing_expired`（超过 7 天）、`own_listing`（不能买自己的）、`not_enough_coins`（带 `need`、`coins`）、`card_moved`。
  - 返回 `{ card, coins, price, tradeTax }`；`card` 是已过户的实例。
- **成交历史与参考价**：`GET /market/history?cardId=...` → `{ sales, priceBand }`。
- **扁平入口**：`/market` 浏览和购买，`/market?view=own` 管理自己的挂单，`/cards?mode=list` 选卡上架。

## 6. 账号绑定（游客 / 邮箱号绑定 osu!，osu! 号补绑邮箱）

背景：市场只给绑定了 osu! 的账号用。`GET /auth/me` 现在多返回 `kind`（`osu` 绑定了 osu!，不管有没有邮箱；`email` 只有邮箱；`guest` 游客）和 `hasEmail`；判断账号类型请看这两个字段，**不要再用 id 前缀猜**（绑定之后邮箱号的 id 还是 `email-xxx`）。`GET /users/:userId/progress` 的 `linkedAccount` 也是同一个意思。

**绑定 osu!**
1. 已登录时让浏览器整页跳转 `/auth/osu/bind`（和登录用的 `/auth/osu` 一样是 `<a href>`），走完 osu! 授权后回到 `${WEB_BASE}/?bind=结果`：
   - `bind=linked`：这个 osu! 号没人用过，已经挂到当前账号，并补发一个神秘卡包去领本体卡（手上已有神秘卡包或本体卡则不补）。刷新账号信息即可。
   - `bind=choose`：这个 osu! 号已经有进度，**还没有改任何东西**，要弹二选一界面。
   - `bind=error&reason=…`：`already_linked`（当前账号已经绑过 osu!）、`session_changed`（授权回来时登录的不是发起的那个账号）、`unknown_user`、`unauthorized`（没登录就点了绑定）。
2. `GET /auth/bind/pending` → `{ pending: null }` 或 `{ pending: { osuId, osuUsername, expiresAt, current, osu } }`。`current` 是现在登录的账号，`osu` 是已经占着这个 osu! 号的账号，两边结构一样：`{ id, username, kind, level, tutorialDone, coins, cardCount, bestRarity, lastSeenAt, createdAt }`，对比界面直接用。待确认只保留 **10 分钟**（`expiresAt` 是毫秒时间戳），过期后要重新点绑定。
3. 玩家选定后 `POST /auth/bind/resolve`，body `{ choice, confirm: true }`：
   - `choice: "keep-current"`：留下当前账号，把 osu! 号挂过来，原来的 osu! 号封存。
   - `choice: "keep-osu"`：留下 osu! 号，当前账号封存（当前账号的邮箱和密码会跟过去，对方没邮箱时），登录态自动换成 osu! 号。
   - `confirm` 必须是 `true`，界面要弹二次确认（"另一边之后无法找回"），点了才带。
   - 成功返回 `{ userId, sealedUserId, kept }`，登录态 cookie 已经换成留下来的账号，前端整体刷新即可。
   - 错误：`no_pending_bind`（404，没有待确认或已过期）、`bind_stale`（409，期间两边账号有变化，重新绑定）。
4. `POST /auth/bind/cancel`：放弃这次待确认。

**封存是什么**：落选账号不删数据、**不合并**，只是登不上：邮箱和 osu! id 释放出来，在售挂单自动下架并退押金，进行中的出征放弃（体力退回，没有奖励）。带着封存账号登录态的请求会被当作没登录，cookie 会被清掉。

**补绑邮箱（反向绑定）**：`POST /auth/email/bind`，body `{ email, password }`（密码至少 8 位），给没有邮箱的账号（osu! 号、游客都行）补邮箱和密码，之后可以用邮箱登录同一个账号。错误：`email_taken`（409）、`email_already_bound`（409，已经有邮箱）、`invalid_email`、`invalid_input`。

## 8. 洗技能（碎片 + 金币，逢 5 自选）

规则见《经济与养成系统 v0.3》§6.4。对一张**非本体卡**的指定技能槽（0、1、2）重洗；每张卡单独计数，第 1 到 4 次随机，第 5 次自选，然后归零。

**看状态**：`GET /users/:userId/cards/:userCardId/reroll-skill`

```
{
  userCardId,
  skillRerollCount,        // 0..4，已随机洗了几次
  pityInterval: 5,
  remainingUntilSelect,    // 还要随机几次才轮到自选，0 表示这次就能自选
  selectReady,             // true：这次必须指定 skillId
  cost: { coins, shards, shardItemId },   // 这次要花的金币、碎片数、碎片道具 id（如 shard-R）
  candidates: [ { ...技能信息, desc } ]    // 合法候选池，已排除这张卡现有的技能
}
```

**执行**：`POST /users/:userId/cards/:userCardId/reroll-skill`，body `{ slot: 0|1|2, skillId?: string }`。

- `selectReady` 为 `false` 时**不能传** `skillId`（`select_not_ready`）；为 `true` 时**必须传**，且要在 `candidates` 里（`skill_id_required` / `invalid_skill_id`）。
- 返回：`{ card, slot, mode: "random" | "select", previousSkillId, newSkillId, skillRerollCount, pityInterval, selectReady, coinsSpent, shardsSpent, shardItemId, coins, items }`。`card` 是换完技能后的整张卡，`coins`、`items` 直接覆盖本地。
- 错误：`not_found`（404）、`hero_protected`（本体卡）、`in_expedition`（出征中）、`card_listed`（挂在市场上）、`invalid_slot`、`empty_skill_pool`、`not_enough_coins`（带 `need`、`coins`）、`not_enough_items`（碎片不足，带 `itemId`、`need`、`have`）。
- 界面建议：确认框里写清"随机，第 N / 5 次"或"自选"，以及要花多少金币和碎片；随机洗是**不可撤销**的。

## 9. 统一商店

规则见《经济与养成系统 v0.3》§6.5，货架在 `content/shop.json`。商品全部限购，产出全部绑定，不进市场。

**看货架**：`GET /users/:userId/shop` → `{ items: [...] }`，每项：

```
{ id, name, summary,
  section,        // "supply" 日常补给 | "gamble" 碎片博弈 | "pity" 碎片保底，前端按它分栏
  period,         // "daily" | "weekly"
  limit, used, remaining,   // 本周期限购、已买、还剩
  nextResetAt,    // 下次重置的毫秒时间戳，做倒计时
  cost:   { coins?, items?: [{ itemId, count }] },
  reward: { kind: "fixed", stamina?, items?, packs? }
        | { kind: "gamble", pool: [{ weight, items }] } }
```

- `gamble` 的奖池带权重，**可以直接算概率展示**（概率 = `weight` ÷ 全部 `weight` 之和）；别在界面上写死数字。
- 体力药水也在货架里，和旧的 `POST /users/:userId/stamina/potion` **共用同一个每日上限**，买哪边都扣同一个额度。

**购买**：`POST /users/:userId/shop/buy`，body `{ itemId, count?: 1..10 }`（`count` 默认 1）。

- 返回：`{ itemId, count, used, remaining, coins, items, granted: { stamina, items, packs } }`。`granted` 是这次实际拿到的东西，博弈箱开出什么就看它；`coins`、`items` 直接覆盖本地。`count > 1` 的博弈箱每份各抽一次。
- 错误：`unknown_shop_item`、`shop_limit_reached`（带 `used`、`limit`、`remaining`）、`not_enough_coins`（带 `need`、`coins`）、`not_enough_items`（碎片不够，带 `itemId`、`need`、`have`）、`stamina_full`（买体力药水时体力已满 720）。
- **注意**：商店目前**不设解锁检查**（测试期间不锁），`content/unlocks.json` 里也没有商店这一项，前端也不要自己加锁。以后会把商店放进"第一天的解锁进度"，等整理玩家流程时再定。旧的体力药水接口仍有 Lv9 + 完成引导的限制。
- **前端入口**：扁平界面的商店页（`/shop`，见《扁平界面设计 v0.1》5.3），桌面顶栏的「商店」也跳到这一页；桌面上没有商店面板。前端没有加解锁检查。

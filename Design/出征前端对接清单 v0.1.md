## 2. 接口一览

路径前缀都是 `/api/users/:userId/expeditions`。成功返回 `{ ok: true, data }`，失败返回 `{ ok: false, error: { code, message, ...extra } }`，`message` 已经是中文，可直接显示。

| 方法 | 路径 | 请求体 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/maps` | — | `MapListing[]` | 地图列表，见 §3 |
| GET | `/current` | — | `ExpeditionView \| null` | 当前未结束的出征（进行中或已挂起）。**读取时服务端顺便做到期结算** |
| POST | `/` | `{ mapId, cardIds, allocation }` | `ExpeditionView` | 开始出征，见 §4 |
| POST | `/current/node` | `{ to }` | `ExpeditionView` | 走到下一个节点（只能走 `availableNext`） |
| POST | `/current/story` | `{ choices }` | `ExpeditionView` | 看完剧情；`choices` 按顺序给出每个选项菜单选了第几项（从 0 数） |
| POST | `/current/event` | `{ choice }` | `ExpeditionView` | 处理事件节点：选第几个选项（从 0 数）；效果只有加减威胁、按比例扣队伍血、给奖励、设标记 |
| POST | `/current/battle/lineup` | `{ lineup }` | `ExpeditionView` | 选本场上阵的卡（`userCardId`，数量必须等于 `allocation.slots`） |
| POST | `/current/battle/actions` | `{ base, actions }` | `ExpeditionView` | 上传战斗操作，见 §5 |
| POST | `/current/battle/retry` | — | `ExpeditionView` | 战败后同种子重试 |
| POST | `/current/settle` | — | `ExpeditionSettlement` | 结算：走到终点是"通关结算"，中途是"到此结算" |
| POST | `/current/abandon` | — | `ExpeditionSettlement` | 放弃：什么奖励都不要，体力全退 |
| POST | `/current/suspend` | — | `ExpeditionView` | 保存并退出（状态变 `suspended`） |
| POST | `/current/resume` | — | `ExpeditionView` | 继续（`suspended` → `active`） |

挂起（`suspended`）期间，除 `resume`、`settle`、`abandon`、读取之外的操作都返回 409 `suspended`。

## 3. 地图列表 `MapListing`

```ts
{ id, kind: "main"|"season"|"weekly"|"daily", name, summary,
  staminaCost, deckSize, fights, maxStars,
  endsAt,      // 现在开始的话，这次出征到什么时候结束（ISO 时间）
  startable,   // 目前恒为 true（事件节点已支持），字段保留
  clears, bestStars,
  objectiveCount, bestObjectives } // 通关目标数量 / 历史最多达成几个；没写目标的图是 0 / 0
```

- `endsAt` 与现在相差不足 1 小时，开始前的确认框要提示"本图将于 X 结束"。
- 日常图每天北京时间 4:00 换图，周常图周一 4:00 换图，出征保留 24 小时，以先到者为准。
- 主线、赛季不扣体力（`staminaCost` 为 0）。

## 4. 开始出征

请求：`{ mapId, cardIds: number[], allocation: { slots, apUpgrade, maxRarity } }`

- `cardIds` 必须正好 `deckSize` 张，不能重复，都得是自己的卡，且不在市场挂牌。
- `allocation` 是远征点数分配（卡槽 4 到 7、AP 上限升级、稀有度权限），校验用共享的 `allocationError`，前端可先本地校验再提交。本体卡不受稀有度限制。
- 体力开始时冻结，结算时才算：拿到东西才扣，无所得或放弃退回。
- 开始前的确认框**必须**包含这句话（产品要求）：
  > 本次出征锁定当前卡组与卡牌状态，期间强化不会生效，参战的卡不能出售或分解。
- 开始后卡组和地图都存了快照：途中强化不影响本次出征，卡牌被服务端锁定（不能出售、分解、被喂、被融合）。

错误码：`expedition_open`(409) 已有未结束出征；`unknown_map`(404)；`map_unavailable`(400)；`bad_pool`(400)；`bad_allocation`(400)；`rarity_locked`(400)；`card_listed`(400)；`not_enough_stamina`(400)。

## 5. 战斗流程（最重要）

一个战斗节点的状态走向：`preparing` →（选阵容）→ `fighting` →（打赢）`won` 或（打输）`lost`。

1. 走到战斗节点后 `battle.status === "preparing"`，让玩家从 `pool` 里选 `allocation.slots` 张上场，调 `battle/lineup`。其余自动成为替补（`battle.bench`）。
2. 前端用 `createBattle(...)` 在本地跑战斗，输入来自 `battle`：`encounter`、`seed`、`apMax`、`hpRatioStart`（作为开场队伍血量比例）、`lineup`、`bench`，卡面用 `pool[].face`。**必须传 `apMax`**。
3. 每回合（或每次操作后）把新增的操作 `BattleAction[]` 上传：`{ base: 服务器已有的条数, actions: 新增部分 }`。一次最多 300 条，整场最多 3000 条。
   - 服务端从头复算整场战斗，以它的结果为准：胜负、星数、掉落都由服务端算。
   - `base` 对不上返回 409 `out_of_sync`，`error.have` 是服务器已有条数；前端应刷新 `current` 后用 `battle.actions` 重放出局面。
   - 非法操作返回 400 `invalid_action`，`error.index` 是本次上传里第几条出错。
   - 刷新页面或断线后，用 `GET /current` 的 `battle.actions` 重放即可恢复，这就是自动存档。
4. 打赢后 `battle.status === "won"`、`nodeDone === true`，`stars` 是本场星数，奖励累计进 `pending`，用 `availableNext` 继续走。
5. 战败后让玩家三选一：
   - **同种子重试**：`battle/retry`。种子不变，不惩罚，卡组和队伍血量回到进入节点时的样子，需要重新选阵容；`retries` 只做统计。
   - **到此结算**：`settle`，只发已累计的奖励，不记通关。
   - **直接退出**：`abandon`，不要任何奖励，体力退回。
6. 随机全部走种子，敌人意图公开。

### 其他节点

| 节点类型 | 前端怎么做 |
|---|---|
| `battle` / `boss` | 如上 |
| `story` | 用 `story.lines` 展示；`choice` 行是选项菜单；看完调 `story` 提交 `choices` |
| `treasure` | 进入节点时服务端已掷好并累计，`pending` 里能看到；直接继续走 |
| `rest` | 队伍血量回满，`hpRatio` 变 1 |
| `empty` | 空地，到达即 `nodeDone`，什么都不发生；前端画成灰色足迹格 |
| `branch` | 只是分叉，`availableNext` 里有多个选项让玩家选 |
| `event` | 在地图内详情展示标题、正文和公开选项效果；到达节点后选一项，调 `event` 提交 `{ choice }`（从 0 数）；选完 `nodeDone` 变 true，不选不能走 |

地图画图用 `map.nodes[id].pos`（可选坐标）和 `next`；当前位置 `position`；`requires.flag` 没满足的分支已被 `availableNext` 过滤掉。

`ExpeditionView.nodePreviews` 只含当前格、前方一步、身后一步的公开详情（服务端不下发更远的）：战斗遭遇（含基础生命与公开弱点）、事件选项、剧情和奖励确定时机。预览不包含随机掉落结果；已获得的奖励以 `pending` 为准。点节点只打开详情，不发移动请求；详情里的「前往下一站」只在当前节点已处理且所选节点在 `availableNext` 中时出现。

## 6. 必须做的界面

1. **地图选择**：按 `kind` 分栏（主线 / 日常 / 周常 / 赛季），显示体力、卡池张数、战斗数、最高星数、`startable`。
2. **出征准备**：选满 `deckSize` 张卡、分配远征点数、确认框（含 §4 的那句话与不足 1 小时提示）。
3. **地图/节点页**：默认聚焦当前位置，详情默认关闭；可缩放和平移，也可切换全图。点击节点打开悬浮详情，宽屏贴近节点、窄屏停靠地图底部，均不挤占地图布局。页面显示 `pending` 累计奖励、星数；底部并排展示完整卡面，窄屏可横滑。每张卡下的血条都读取同一个队伍 `hpRatio`，不是单卡血量。
4. **战斗**：见 §5。战斗页要能从服务端 `battle` 恢复。
5. **"未完成出征"提示**：登录后读 `GET /current`，非空就弹出，提供**继续**、**到此结算**、**放弃**三个选项。
   扁平界面首页的远征卡也读 `GET /current`：写地图名、还剩多久、队伍血量、星数和 `pending`，按钮整页跳到远征页，由这个提示接手（见《扁平界面设计 v0.1》第 5.1 节）。
6. **保存并退出**按钮：调 `suspend`，与自动存档是同一份进度，不做回档、不做多存档位。
7. **结算页**：展示 `ExpeditionSettlement`（`end`、`rewards`、星数、体力扣还）。`viaMail` 为 true 表示奖励走邮件（到期结算）。
8. 卡册里被出征锁定的卡打角标并置灰分解/出售/喂养/融合按钮（服务端已拦，错误码 `in_expedition`）。

## 7. 前端要注意的事

- 同一时间只有一个出征（含挂起）。开始前先读 `current`。
- 出征期间队伍 HP 跨战斗保留（`hpRatio`），状态每场刷新。
- 卡的数值来自出征开始时的快照 `pool[].face`，不要再用卡册里的最新数据。
- 出征到期（24 小时或换图）后，已拿到的奖励由服务端发邮件、体力按"拿到才扣"处理；读取 `current` 时顺便结算，前端无需轮询。到期后再操作会返回 410 `expedition_expired`，提示玩家去邮箱看。
- 练习战与教学战不走出征接口，仍是纯本地战斗（卡槽 4 张、AP 上限 6，用 `FREE_ALLOCATION`）。

## 7.5 难度（威胁值与档位）

- 难度只由大地图格子和事件选项改变，打赢杂鱼不涨。服务端算好，前端**不传任何难度数据**，直接展示 `ExpeditionView.difficulty`：
  `{ threat, tier(1–5), hpMult, lootMult, nextTierAt(下一档要多少威胁值，最高档 null), thresholds }`。
- 建议做一条威胁条：当前 `threat`、各档 `thresholds` 刻度、当前档位；走进带威胁的格子后数字会跳，档位变化要有提示。
- 进入战斗节点时，敌人血量已按档位放大并存进 `battle.encounter`（重放、重试都是同一份），前端照常用，不要自己再乘。
- 掉落的主产（金币、精华、玩家经验、物品、卡包）按 `lootMult` 放大；星级加成和首通奖励不放大。**默认倍率全是 1（不放大）**，只有地图配置里写了 `difficulty.lootMult` 的图才放大。
- 休息点只回血，不降威胁。战斗中档位不变。
- `ExpeditionSettlement` 新增 `tier`（通关时档位）、`objectives`（`[{text, met}]`，地图写了通关目标才有）。写了通关目标的图，通关星数 = 达成的目标数（例如"3 档及以上通关""得到某标记"）。
- `MapDef.nodes[id].threat`：地图节点上的威胁加减，地图预览可以标"危险"图标；`MapDef.objectives` 可以在选图时预先展示。
- 日常图可能带标题"危险路线"的分支（威胁 +N，掉落更多）。

## 8. 错误码速查

| 状态 | code | 含义 |
|---|---|---|
| 404 | `no_expedition` | 没有进行中的出征 |
| 410 | `expedition_expired` | 出征已到期，奖励走邮件 |
| 409 | `suspended` | 已保存并退出，先 `resume` |
| 409 | `expedition_open` | 开始时已有未结束的出征 |
| 409 | `out_of_sync` | 上传操作的 `base` 对不上，`error.have` 是服务器条数 |
| 400 | `node_unfinished` / `bad_move` | 节点没处理完 / 走不到那个节点 |
| 400 | `no_story` / `bad_choices` | 当前没有剧情 / 选项数量或编号错 |
| 400 | `no_event` / `bad_choice` | 当前没有待处理的事件 / 事件选项编号错 |
| 400 | `no_battle` / `not_fighting` / `already_started` | 战斗状态不对 |
| 400 | `bad_lineup` | 上阵张数不对，或卡不在卡池 |
| 400 | `invalid_action` / `too_many_actions` | 操作不合法 / 操作太多 |
| 400 | `not_lost` | 只有战败才能重试 |
| 400 | `map_unavailable` | 地图含暂不支持的节点 |
| 400 | `bad_pool` / `bad_allocation` / `rarity_locked` / `card_listed` / `not_enough_stamina` | 开始出征时的校验 |
